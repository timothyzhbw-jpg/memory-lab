# Memory Lab web page

English | [中文](ui.zh-CN.md)

`memlab-ui` is a local, read-only web page for trying MemFalsify and orgmemory without learning the command line. It
runs on your own computer, reads one project folder, and never changes a file. It uses the same library code as the
`memfalsify` and `orgmemory` commands and follows the same confinement rules as the [MCP server](mcp.md).

## Install and run

From a checkout of this repository:

```bash
pip install -e packages/memcore -e packages/memfalsify -e packages/orgmemory -e packages/memlab-ui
memlab-ui --root examples
```

`./scripts/setup-local.sh` installs it too. The command prints the address to open, `http://127.0.0.1:8765/` by
default. Press Ctrl+C to stop it.

| Option | Meaning |
|---|---|
| `--root DIR` | The project folder the page may read (default: the current directory). Paths outside it are refused; a file hard-linked into it from elsewhere is read like any other (see *Hard links* below). |
| `--port N` | Port on 127.0.0.1 (default 8765; `0` picks a free port and prints it). A busy port exits with code 2. |
| `--host HOST` | Only `127.0.0.1` is accepted. Any other value exits with code 2: the page has no login, so other machines must not reach it. |
| `--allow-model-verifiers` | Offers the `llm`, `jev`, `dual` and `cascade` verifiers under *More options*, on the address with the key that memlab-ui then prints (see *Model checks need the key* below). They send memory and evidence text to external APIs and cost money; see [local-setup.md](local-setup.md) for their API keys. |

Every page reads in English or Simplified Chinese. `?lang=zh` selects Chinese; links and forms keep the
language, and the *English / 中文* link at the foot of the sidebar switches it on the same page.

## Pages

Forms use GET, so every result has its own address that can be reloaded or bookmarked, and no request changes
anything.

### Home

What Memory Lab is, a *Which file should I check?* box that checks a file against the whole project in one step,
and *Agent files in this project*: the files `memfalsify discover` finds (CLAUDE.md, AGENTS.md, GEMINI.md, Cursor,
Copilot and Windsurf rules) plus any `MEMORY.md`, with the number of statements in each.

### Check an agent file

Pick an *Agent file* and what to *Compare against*: the whole project (the default) or one folder. *More
options* holds:

- *Only statements changed since*: a branch, tag or commit. The page then runs `memfalsify diff` and checks only
  the statements added or changed since that revision; unchanged ones are not checked again. It is offered only
  when the root folder is the top of a git repository, and, as for the MCP tools, the repository's work tree, git
  directory, common directory and object store must all be inside the root.
- *Treat today as*: the reference date for old dates in the file (`--as-of`).
- *Reviews file*: a `reviews.jsonl` of human-confirmed reviews. Its paths must point into the folder you compare
  against.
- *How to compare*: only with `--allow-model-verifiers`. The `openai` verifier (OpenAI or any
  OpenAI-compatible endpoint) is not offered here yet: it needs a model name and a provider or base URL, and
  the page has no inputs for them. Run it with `memfalsify audit --verifier openai --openai-model ...` or
  through memlab-mcp's `--openai-*` options; see *OpenAI-compatible providers* in
  [local-setup.md](local-setup.md).

Memory Lab's own files are never evidence. They are recognised by their content, not their name: review records
(lines with a `memory_id`, `relation`, `quote` and `reviewer`), decision logs (events, evidence manifests,
`policy.json`, role changes, importer settings and sync state) and reports or exports that MemFalsify or orgmemory
generated (Markdown and HTML reports, JSON output, ADRs and the decision CSV). Each is listed under *Files left
out* with its reason: *review records*, *decision log* or *report generated by Memory Lab*. Ordinary CSV and JSON
Lines files stay evidence. The file being checked and the files it links to are left out too, as in
`memfalsify audit`.

The result is the `memfalsify audit` report in plain words:

| Tile | Statuses |
|---|---|
| *Look at these* | `challenged`, `conflicted`, `candidate_counterevidence` (possible counterevidence), `disputed` |
| *Similar text found* | `supported`, `candidate_support`: a passage that looks alike. For the quick check that is a word match, not proof. |
| *Can't tell* | `insufficient_evidence` |

With nothing to look at, the heading says *No contradictions found in MEMORY.md*, followed by *N statements
couldn't be checked* when some had no evidence.

Each statement to look at is a card: *Your agent file says* with a short `file:line` label, next to *Your docs
say* with the quote that seems to disagree, the differing words or numbers highlighted (for the lexical verifier's
own matches), why it was flagged, and one line of advice. More sources and wording issues (*always*, *next week*,
guesses, duplicates) follow. The technical facts are folded under *Details* on each card: the statement ID, the
full paths, source links and SHA-256 hashes. The other statements are folded under *Show the N other statements*,
and files left out of the comparison under *N files were not read*. A closing note says that the quick check
matches words: it can miss a source that says the same thing in other words and can flag a sentence that only
looks like a disagreement.

### Team decisions

The first decision log under the root opens straight away; the *Decision log* picker lists every folder under the
root with `events.jsonl`, `policy.json` and `evidence.jsonl` (and optionally `policy-log.jsonl`). *More options*
can look at the log as it was at the end of a day: a date means the whole day in UTC, every event before the next
midnight.

- The sidebar lists the log's topics (subjects) with their status: *Approved*, *Rejected* or *Waiting*
  (`proposed`).
- A banner says how many things need attention: the findings of `orgmemory audit` (stale after 14 days, measured
  at the chosen day or now), each written as a plain sentence.
- For the chosen topic: who decided, with which role and when, the quote the decision is based on, what it is
  waiting for, open risks and dependencies, its findings, and *How we got here*: every event in replay order with
  its quote, marked *Counted* (an authorized decision), *Noted* (an authorized request, risk, dependency or comment)
  or *Not counted* (for example *account manager can't approve*). Event IDs, paths, source links and hashes are
  folded under *Details*. Names and roles are shown as the log writes them.
- *What changed between two dates* runs `orgmemory changes` for the events after the first day and up to the end
  of the second (UTC).

## Safety

The page follows the [MCP server's](mcp.md) rules, adapted to a browser:

- **Loopback only.** It binds 127.0.0.1 and refuses any other `--host`. Requests from another address are
  refused.
- **DNS rebinding.** Every request must carry exactly one `Host` header naming `127.0.0.1` or `localhost` with
  the server's port; anything else gets 403 without echoing the header. A page on another site that makes its
  own name resolve to 127.0.0.1 therefore gets nothing.
- **Cross-site requests.** Before any work, a request is refused (403) when its `Sec-Fetch-Site` header is present
  and not `same-origin` or `none`, or its `Origin` header is present and not exactly the server's own origin. A
  page on another site therefore cannot make the server run checks with an image or a frame. Opening the address,
  a bookmark or the page's own links still works, and a quick (lexical) check keeps its own bookmarkable address.
- **Model checks need the key.** With `--allow-model-verifiers`, memlab-ui makes a random key when it starts and
  prints the address with it (`http://127.0.0.1:8765/?key=...`) in the terminal only, as Jupyter does. A model
  check runs only for a request that carries that key; pages pass it on in their links and forms only to a
  visitor whose request already had it, so a visitor without it never sees it. This keeps other users of the same
  computer, and websites that make a browser or another program send requests here, from sending your files to a
  model or spending your API credit, as long as they cannot read your terminal. Quick (lexical) checks need no key.
  A restart makes a new key.
- **Bounded work.** These limits are best-effort robustness against your own project's content, not a security
  boundary: they keep a very large or unusual project from tying up the page. At most 2 pages are computed at once (others get 503 with `Retry-After`), at most 16
  connections are served at once (more are closed straight away), and the request line and headers must arrive
  within 10 seconds in total, however slowly. Each page reads at most 8 MB from one file and 64 MB in all,
  counted in bytes as they are read (a file that grows while being read, or streams line by line, is stopped at
  the limit), git objects included. It walks at most 20,000 folders and lists at most 100,000 directory entries
  across discovery, the lists and the evidence scan, at most 64 levels deep. It parses at most 5,000 statements and
  checks at most 1,000, builds at most 5,000 evidence passages and makes at most 2,000,000 statement-to-passage,
  statement-to-statement (internal conflicts) and old-to-new statement comparisons; each is counted while it is
  built. Media files are hashed within the same byte limits (a transcript or OCR file whose media file is over
  them is left out with that reason). An agent file over 256 KB is refused before it is parsed. A page that
  reached a limit says
  *This project is large, so only part of it was read*; *Only statements changed since* refuses instead when either
  version of the file is too large to compare. Evidence files over 2 MB are skipped after reading at most 2 MB and
  one byte.
- **Read-only.** Only GET and HEAD are answered (every other method gets 405), every form uses GET, and no page
  writes a report, appends an event, records a review or applies a patch. Git runs with `GIT_OPTIONAL_LOCKS=0`, so
  it does not refresh the index either. The tests snapshot the root before and after visiting every page.
- **Confinement.** Every path in a request is resolved inside `--root`: relative paths, and absolute ones only
  when they stay inside; `..` and symlinks only when the resolved path stays inside. Hidden files and folders,
  `node_modules`, `__pycache__` and `venv` are refused except at a documented agent instruction location such as
  `.cursor/rules/`. Each page runs inside `memcore`'s confined reads, so a file swapped for an outward symlink after
  these checks is still refused when it is opened. Without POSIX `O_NOFOLLOW` and `dir_fd` support (Windows) the
  server refuses to start. The lists the forms offer come from the same walk and skip nested git repositories and
  symlinked folders.
- **Hard links.** As everywhere in Memory Lab, reads follow hard links: a hard link is another name for the same
  file and cannot be told apart from it, so a file hard-linked into the root from elsewhere on the same filesystem
  is read. A git clone cannot contain hard links, and making one needs write access to the folder, so serve only
  folders you control.
- **Model verifiers off.** The default is the offline lexical verifier. A request for `llm`, `jev`, `dual` or
  `cascade` gets 403 unless the server was started with `--allow-model-verifiers`. A request for `openai` gets
  400 on every server: the page does not offer it.
- **Untrusted text stays text.** Memory, evidence, file names, reviews, event logs, policy names and source URIs
  go through `memcore.htmlpage`: escaped, with control, bidi and other invisible characters shown as `U+XXXX`. Only
  `http` and `https` sources become links. The language switch links only to the page's own routes and known
  fields. The document is 7-bit ASCII.
- **Strict headers.** Pages send `Content-Security-Policy: default-src 'none'; img-src 'self'; style-src
  'unsafe-inline'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'` (the same policy without
  `frame-ancestors` is also in a meta tag), plus `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: no-referrer` and `Cache-Control: no-store`. The four images (the logo in light and dark, and two
  favicons) are served from the package at `/static/` by exact name, with `Content-Security-Policy: default-src
  'none'; frame-ancestors 'none'`, the same `X-Content-Type-Options`, `X-Frame-Options` and `Referrer-Policy`, and
  `Cache-Control: max-age=3600`. There is no JavaScript, no cookie and no external resource: styles are inline,
  icons are inline SVG and fonts are the system's. A request without an HTTP version (HTTP/0.9) gets a 400 framed as
  HTTP/1.0, so every reply carries these headers.
- **Errors without details.** An error is one sentence. It never contains a traceback, a path outside the root,
  git's own diagnostics or the contents of a rejected file, and a value outside the root is not shown back in the
  form. The terminal log has one line per request: the method, a known route or `-`, and the status, never the
  query or a header; an unexpected failure prints one fixed line, without a traceback.

## Limitations

- There is no login. Other programs and other users on the same computer can open the address and read what the
  page shows from the root, so run it on a computer you do not share, or choose a root you are happy to show.
- A browser that sends neither `Sec-Fetch-Site` nor `Origin` (older browsers) is not protected from cross-site GET
  requests for quick checks; they can make the server run them within the limits above, but cannot read the
  answers, cannot start a model check without the key, and no request changes anything.
- The page does not save reports. To share one, run the CLI with `--format html`.
- Folders are offered as *Compare against* choices down to four levels.
- The names, roles and quotes on a page are the data's own and are not translated.
