# Memory Lab 网页

[English](ui.md) | 中文

`memlab-ui` 是一个在本机运行的只读网页，不用学命令行就能试用 MemFalsify 和 orgmemory。它只读取一个项目文件夹，
从不修改任何文件。它调用的库代码与 `memfalsify`、`orgmemory` 命令相同，路径限制规则与 [MCP 服务器](mcp.zh-CN.md)
一致。

## 安装与运行

在本仓库的检出目录中：

```bash
pip install -e packages/memcore -e packages/memfalsify -e packages/orgmemory -e packages/memlab-ui
memlab-ui --root examples
```

`./scripts/setup-local.sh` 也会安装它。命令会打印要打开的地址，默认是 `http://127.0.0.1:8765/`。按 Ctrl+C 停止。

| 选项 | 含义 |
|---|---|
| `--root DIR` | 网页可以读取的项目文件夹（默认是当前目录）。它之外的路径会被拒绝；从其他位置硬链接进来的文件会像普通文件一样被读取（见下文“硬链接”）。 |
| `--port N` | 127.0.0.1 上的端口（默认 8765；`0` 表示选一个空闲端口并打印出来）。端口被占用时以退出码 2 结束。 |
| `--host HOST` | 只接受 `127.0.0.1`，其他值以退出码 2 结束：网页没有登录，不能让其他机器访问。 |
| `--allow-model-verifiers` | 在 memlab-ui 随后打印的带密钥地址上，于“更多选项”中提供 `llm`、`jev`、`dual` 和 `cascade` 验证器（见下文“模型检查需要密钥”）。它们会把记忆和证据文本发送给外部 API 并产生费用；API 密钥设置见 [local-setup.zh-CN.md](local-setup.zh-CN.md)。 |

每个页面都有英文和简体中文两种语言。`?lang=zh` 选择中文；链接和表单会保留所选语言，侧栏底部的“English / 中文”
链接可以在同一页面上切换。

## 页面

表单都使用 GET，所以每个结果都有自己的地址，可以刷新或收藏，任何请求都不会改变任何东西。

### 首页

介绍 Memory Lab 是什么；“要检查哪个文件？”框一步把一个文件与整个项目对照；“本项目中的 Agent 文件”列出
`memfalsify discover` 找到的文件（CLAUDE.md、AGENTS.md、GEMINI.md，以及 Cursor、Copilot、Windsurf 规则）
和所有 `MEMORY.md`，并给出每个文件的陈述数量。

### 检查 Agent 文件

选择“Agent 文件”和“对照范围”：整个项目（默认）或某一个文件夹。“更多选项”包括：

- “只看此后改动的陈述”：一个分支、标签或提交。页面随后运行 `memfalsify diff`，只检查该修订之后新增或改动的
  陈述，未改动的不再重新检查。只有当根文件夹是 git 仓库的顶层时才提供；与 MCP 工具一样，仓库的工作区、git 目录、
  公共目录和对象库都必须位于根文件夹之内。
- “把今天当作”：判断文件中旧日期的基准日期（`--as-of`）。
- “审阅文件”：记录了人工确认的 `reviews.jsonl`。其中的路径必须指向对照范围内的文件。
- “对照方式”：只有加上 `--allow-model-verifiers` 时才出现。

Memory Lab 自己的文件从不作为证据。它们按内容而不是文件名识别：审阅记录（含 `memory_id`、`relation`、`quote`
和 `reviewer` 的行）、决策日志（事件、证据清单、`policy.json`、角色变更、导入器设置和同步状态），以及 MemFalsify
或 orgmemory 生成的报告和导出（Markdown 和 HTML 报告、JSON 输出、ADR 和决策 CSV）。每个文件都列在“未参与对照的
文件”中并注明原因：“审阅记录”“决策日志”或“Memory Lab 生成的报告”。普通的 CSV 和 JSON Lines 文件仍是证据。与
`memfalsify audit` 一样，被检查的文件及其链接的文件也不算证据。

结果就是用平实语言呈现的 `memfalsify audit` 报告：

| 卡片 | 状态 |
|---|---|
| “需要看一下” | `challenged`、`conflicted`、`candidate_counterevidence`（可能的反证）、`disputed` |
| “找到相似说法” | `supported`、`candidate_support`：有一段看起来相似的文字。对快速检查来说，这只是字词相近，不代表一定正确。 |
| “无法判断” | `insufficient_evidence` |

没有需要看的内容时，标题是“MEMORY.md 里没有发现矛盾”，如果有陈述找不到证据，后面再加上“另有 N 条无法核对”。

每条需要看的陈述是一张卡片：“你的 Agent 文件写道”及简短的 `文件:行号` 标签，旁边是“你的文档写道”和看起来有出入
的引文，不同的词语或数字会被高亮（仅限词法验证器自己的匹配），并说明为什么被标出，再给一句建议。之后是更多来源和
措辞问题（“总是”“下周”、猜测、重复）。技术细节折叠在每张卡片的“详情”里：陈述 ID、完整路径、来源链接和 SHA-256
哈希。其余陈述折叠在“显示其余 N 条陈述”下，未参与对照的文件折叠在“N 个文件未读取”下。最后的说明指出快速检查比较
的是词语：它可能漏掉换了说法的来源，也可能标出只是看起来矛盾的句子。

### 团队决策

根文件夹下的第一个决策日志会直接打开；“决策日志”选择框列出根文件夹下所有包含 `events.jsonl`、`policy.json` 和
`evidence.jsonl`（以及可选的 `policy-log.jsonl`）的文件夹。“更多选项”可以查看截至某一天结束时的状态：日期表示
UTC 的一整天，即下一个午夜之前的所有事件。

- 侧栏列出日志中的主题（subject）及其状态：“已批准”“已拒绝”或“待定”（`proposed`）。
- 横幅显示有多少处需要注意：即 `orgmemory audit` 的发现（超过 14 天视为停滞，以所选日期或当前时间计算），每条都
  写成一句平实的话。
- 对于所选主题：谁以什么角色在何时作出决定，决定依据的引文，正在等待什么，未解决的风险和依赖，相关的发现，以及
  “事情经过”：按回放顺序列出的每个事件及其引文，标为“算数”（有权限的决定）、“已记录”（有权限的请求、风险、依赖或
  评论）或“不算数”（例如“account manager无权批准”）。事件 ID、路径、来源链接和哈希折叠在“详情”里。人名和角色按
  日志原样显示。
- “两个日期之间的变化”对第一个日期之后、到第二个日期结束为止（UTC）的事件运行 `orgmemory changes`。

## 安全

网页遵循 [MCP 服务器](mcp.zh-CN.md)的规则，并针对浏览器做了调整：

- **只监听本机回环地址。** 绑定 127.0.0.1，拒绝其他任何 `--host`。来自其他地址的请求会被拒绝。
- **防 DNS 重绑定。** 每个请求必须恰好带一个 `Host` 头，内容是 `127.0.0.1` 或 `localhost` 加上服务器端口；
  其他情况返回 403，且不回显该头部。其他网站即使把自己的域名解析到 127.0.0.1，也拿不到任何内容。
- **跨站请求。** 在做任何工作之前，如果请求带有 `Sec-Fetch-Site` 头且其值不是 `same-origin` 或 `none`，或者带有
  `Origin` 头且不完全等于服务器自己的源，就返回 403。因此其他网站无法用图片或框架让服务器运行检查。直接打开地址、
  书签和页面自己的链接都不受影响，快速（词法）检查的结果地址仍可收藏。
- **模型检查需要密钥。** 启用 `--allow-model-verifiers` 时，memlab-ui 启动时会生成一个随机密钥，并只在终端里打印
  带密钥的地址（`http://127.0.0.1:8765/?key=...`），与 Jupyter 的做法相同。只有带着这个密钥的请求才能运行模型检查；
  页面只在当前请求已经带有密钥时才把它放进链接和表单，所以没有密钥的访问者永远看不到它。只要读不到你的终端，同一台
  电脑上的其他用户，以及让浏览器或其他程序向这里发请求的网站，都无法把你的文件发送给模型或消耗你的 API 额度。快速
  （词法）检查不需要密钥。重启后密钥会更换。
- **工作量有上限。** 这些上限是针对你自己项目内容的尽力而为的稳健性措施，而不是安全边界：它们防止很大或不寻常的
  项目占住页面。同时最多计算 2 个页面（其余返回 503 并带 `Retry-After`），同时最多服务 16 个连接（多出的
  连接立即关闭），请求行和所有请求头必须在 10 秒内全部到达，不管发送得多慢。每个页面从单个文件最多读取 8 MB、
  总共最多 64 MB，按实际读取的字节计数（读取中变大或逐行读取的文件会在达到上限时停止），git 对象也计算在内。在发现、
  列表和证据扫描中总共最多遍历 20,000 个文件夹、列出 100,000 个目录项，最深 64 层。最多解析 5,000 条陈述、检查
  1,000 条，最多构建 5,000 个证据段落，陈述与段落、陈述与陈述（内部冲突）、新旧陈述之间最多比较 2,000,000 次；
  这些都在构建过程中计数。媒体文件在同样的字节上限内计算哈希（媒体文件超过上限的转写稿或 OCR 文件会注明原因并
  被排除）。超过 256 KB 的 Agent 文件在解析前就会被拒绝。
  达到上限的页面会显示“这个项目很大，只读取了其中一部分”；如果文件的任一版本太大，“只看此后改动的陈述”会直接拒绝。
  超过 2 MB 的证据文件最多只读 2 MB 加一个字节就被跳过。
- **只读。** 只响应 GET 和 HEAD（其他所有方法都返回 405），所有表单都用 GET，没有页面会写报告、追加事件、记录
  审阅或应用补丁。git 以 `GIT_OPTIONAL_LOCKS=0` 运行，也不会刷新索引。测试会在访问每个页面前后对根文件夹做快照
  比较。
- **路径限制。** 请求中的每个路径都在 `--root` 内解析：相对路径可以，绝对路径只有在根文件夹内才可以；`..` 和
  符号链接只有在解析结果仍在根文件夹内时才可以。隐藏文件和文件夹、`node_modules`、`__pycache__` 和 `venv` 都会被
  拒绝，`.cursor/rules/` 这类有文档说明的 Agent 指令位置除外。每个页面都在 `memcore` 的受限读取中运行，所以检查
  之后被替换成向外符号链接的文件，在打开时仍会被拒绝。没有 POSIX `O_NOFOLLOW` 和 `dir_fd` 支持（Windows）时，
  服务器拒绝启动。表单提供的列表来自同一次遍历，并跳过嵌套的 git 仓库和符号链接文件夹。
- **硬链接。** 与 Memory Lab 的其他部分一样，读取会跟随硬链接：硬链接是同一个文件的另一个名字，无法与原文件区分，
  所以从同一文件系统其他位置硬链接进根文件夹的文件会被读取。git 克隆不会包含硬链接，创建硬链接需要对该文件夹有
  写权限，所以只对你自己控制的文件夹运行本网页。
- **默认关闭模型验证器。** 默认使用离线的词法验证器。除非用 `--allow-model-verifiers` 启动，否则请求 `llm`、
  `jev`、`dual` 或 `cascade` 都返回 403。
- **不可信文本始终是文本。** 记忆、证据、文件名、审阅、事件日志、策略名称和来源 URI 都经过 `memcore.htmlpage`：
  转义处理，控制字符、双向文本字符和其他不可见字符显示为 `U+XXXX`。只有 `http` 和 `https` 来源会成为链接。语言
  切换链接只指向本页面自己的路由和已知字段。文档是 7 位 ASCII。
- **严格的响应头。** 页面发送 `Content-Security-Policy: default-src 'none'; img-src 'self'; style-src
  'unsafe-inline'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`（不含 `frame-ancestors` 的同一
  策略也写在 meta 标签中），以及 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、
  `Referrer-Policy: no-referrer` 和 `Cache-Control: no-store`。四张图片（浅色和深色标志、两个网站图标）从软件包中
  按确切文件名在 `/static/` 下提供，带 `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`、同样的
  `X-Content-Type-Options`、`X-Frame-Options` 和 `Referrer-Policy`，以及 `Cache-Control: max-age=3600`。没有
  JavaScript、没有 Cookie、没有外部资源：样式内联，图标是内联 SVG，字体用系统字体。没有 HTTP 版本的请求
  （HTTP/0.9）会得到以 HTTP/1.0 格式发送的 400，所以每个响应都带有这些头部。
- **出错时不泄露细节。** 错误只是一句话，从不包含堆栈跟踪、根文件夹之外的路径、git 自己的诊断信息或被拒绝文件的
  内容；根文件夹之外的值也不会显示回表单中。终端日志每个请求一行：方法、已知路由或 `-`、状态码，从不记录查询
  参数或请求头；意外失败只打印一行固定文字，没有堆栈跟踪。

## 局限

- 没有登录。同一台电脑上的其他程序和其他用户都可以打开这个地址，读取页面从根文件夹中显示的内容。请在不与他人共用
  的电脑上运行，或者选择一个愿意展示的根文件夹。
- 既不发送 `Sec-Fetch-Site` 也不发送 `Origin` 的浏览器（较旧的浏览器）无法防住针对快速检查的跨站 GET 请求；这些
  请求可以让服务器在上述上限内运行检查，但读不到结果，没有密钥也不能启动模型检查，而且任何请求都不会改变任何东西。
- 网页不保存报告。要分享报告，请用 CLI 的 `--format html`。
- “对照范围”中提供的文件夹最多四层深。
- 页面上的人名、角色和引文都是数据本身的内容，不会被翻译。
